# 语法分析器实验报告材料

## 一、设计思路

本实验采用 WinFlexBison 自动生成词法分析器和语法分析器，整体流程分为“词法分析 -> 语法分析 -> 语法树构建 -> 错误恢复与输出”四个阶段。

1. 词法分析阶段
   - 由 `lexer.l` 负责把源程序分解成 token。
   - 识别关键字、标识符、常量、运算符、界符和注释。
   - 对标识符与字面量保留原始词素，供语法树输出使用。

2. 语法分析阶段
   - 由 `parser.y` 定义课程设计风格的分层文法。
   - 表达式采用分层结构：赋值表达式、逻辑或、逻辑与、相等、关系、加减、乘除、单目、基本表达式。
   - 语句层支持声明、复合语句、选择语句、循环语句、跳转语句等。

3. 语法树构建阶段
   - 在 Bison 语法动作中直接创建 AST 节点。
   - 每个文法成分对应一个树节点，便于展示程序结构。
   - 成功分析后输出语法树，方便写实验报告和截图说明。

4. 错误恢复阶段
   - 在声明、表达式语句、复合语句、`if / while / for` 条件等位置加入 `error` 恢复分支。
   - 当局部错误出现时，尽量跳过错误片段并继续分析后续输入。
   - 报错信息包含行号和附近 token，便于定位问题。

5. 输入方式
   - 支持标准输入。
   - 也支持命令行参数指定源文件，例如 `syntax.exe input_normal.txt`。
   - 对 UTF-8 BOM 做了兼容处理，避免某些编辑器保存的文件无法识别。

## 二、关键代码说明

### 1. `parser.y`：语法规则与语法树

#### 1.1 AST 节点定义

在 `parser.y` 的头部定义了 AST 节点结构：

```c
typedef struct ASTNode {
    char *label;
    int child_count;
    struct ASTNode **children;
} ASTNode;
```

含义如下：
- `label`：当前节点名称，例如 `Program`、`WhileStatement`、`Add`。
- `child_count`：子节点数量。
- `children`：子节点数组。

#### 1.2 语法树辅助函数

主要包括以下函数：

```c
static ASTNode *ast_new(const char *label);
static ASTNode *ast_new_token(const char *kind, const char *lexeme);
static void ast_add_child(ASTNode *parent, ASTNode *child);
static void ast_print(ASTNode *node, int indent);
static void ast_free(ASTNode *node);
```

作用说明：
- `ast_new`：创建普通语法树节点。
- `ast_new_token`：创建带词素信息的叶子节点，如 `Identifier:x`。
- `ast_add_child`：把子节点挂到父节点上。
- `ast_print`：按缩进打印语法树。
- `ast_free`：释放语法树内存。

#### 1.3 主入口与错误输出

```c
int main(int argc, char **argv)
```

支持两种输入方式：
- 无参数：从标准输入读取。
- 有参数：读取文件内容。

错误输出函数：

```c
void yyerror(const char *s)
```

输出格式为：

```text
Syntax error at line N near 'token': message
```

便于实验报告中展示“错误定位效果”。

#### 1.4 错误恢复规则

在下列位置加入了 `error`：
- 声明错误：`type_specifier error ';'`
- 表达式语句错误：`error ';'`
- 复合语句错误：`'{' error '}'`
- 控制语句条件错误：`KW_IF '(' error ')' statement` 等

这些规则的作用是：
- 在出现局部语法错误时不中断整个分析过程。
- 尽量继续分析后续语句。
- 让实验展示“容错能力”。

### 2. `lexer.l`：词法识别与 token 传递

#### 2.1 词法规则作用

`lexer.l` 负责把源代码切分成词法单元，并返回给 Bison：
- 关键字：`if`、`while`、`return`、`int` 等
- 标识符：`IDENTIFIER`
- 整数、浮点数、字符串、字符常量
- 逻辑、关系、赋值、算术运算符
- 界符：括号、花括号、分号、逗号

#### 2.2 词素保留

对于标识符和字面量，词法分析器会把原始文本保存在 `yylval.sval` 中：

```c
{ID}    { yylval.sval = dup_text(yytext); return IDENTIFIER; }
{INT}   { yylval.sval = dup_text(yytext); return INT_CONST; }
```

这样语法树输出时可以显示具体内容，例如：
- `Identifier:x`
- `IntConst:10`

#### 2.3 特殊兼容处理

- 跳过单行注释与块注释。
- 跳过空白字符。
- 支持 UTF-8 BOM，避免某些编辑器保存后的文件报错。

## 三、典型测试用例

### 用例 1：正常程序片段

**输入：**

```c
int x = 1;
while (x < 10) {
    x = x + 1;
}
```

**预期结果：**
- 语法分析成功。
- 输出完整语法树。
- 树中应能看到 `Program`、`Declaration`、`WhileStatement`、`Assign`、`Add` 等节点。

**适合截图位置：**
- 终端中“Syntax analysis succeeded.”
- 语法树展开结果

### 用例 2：声明缺少表达式

**输入：**

```c
int x = ;
```

**预期结果：**
- 报告语法错误。
- 错误信息包含行号和附近 token。
- 触发声明错误恢复。

**适合截图位置：**
- `Syntax error at line ... near ';'`
- 错误恢复提示

### 用例 3：缺少分号

**输入：**

```c
int x = 1
```

**预期结果：**
- 报告语法错误。
- 提示缺少 `;`。
- 终止或进入局部恢复。

**适合截图位置：**
- 报错行号
- 预期 token 提示

### 用例 4：错误的复合语句

**输入：**

```c
while (x < 10) {
    x = x + 1
}
```

**预期结果：**
- 报告缺少分号。
- 尽量继续解析后续结构。
- 展示错误恢复能力。

## 五、报告可直接引用的总结文字

本实验基于 WinFlexBison 自动生成工具实现了词法分析和语法分析。词法分析器负责识别关键字、标识符、常量、运算符和界符；语法分析器采用分层表达式文法和语句文法，实现了声明、赋值、条件语句、循环语句和跳转语句的识别。在语法动作中构建了语法树，并在分析成功后输出树形结构，便于观察程序的语法层次关系。同时，实验加入了错误恢复机制和更友好的报错信息，提高了分析器的可用性和调试效率。
